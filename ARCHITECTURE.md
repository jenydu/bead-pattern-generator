# Architecture

Pixel Art to Beads (PA2B): upload pixel art, get a printable bead chart in a chosen brand's colors.
Everything runs client-side. Hosted as static files on GitHub Pages. No server.

## Approach

Core logic is plain Python (numpy + Pillow), run in the browser through Pyodide (CPython on WebAssembly)
inside a Web Worker. JS only handles the UI. The same `core/` runs under pytest and a CLI locally.

First load downloads ~10 MB (Pyodide + numpy + Pillow); the browser caches it afterward.

## Layout

```
core/                  pure Python, no browser imports
  grid_detect.py       estimate true pixel period + offset (x and y)
  clean.py             sample each cell -> one color; optional color unification
  palette.py           load brand CSVs, RGB->Lab, nearest-color match
  pattern.py           Pattern: grid of palette indices, per-color counts, legend
  api.py               entry points the web page calls through Pyodide
  pipeline.py          image -> Pattern, shared by the web page and the CLI
  render.py            Pattern -> SVG chart tiles / sheet (bead code in each cell), PNG preview
data/palettes/         vendored copy of beadcolors/raw/*.csv
tests/
web/                   GitHub Pages root
  index.html style.css app.js worker.js
  py/                  copy of core/ + data/ (generated by build.py)
build.py               sync palettes from ../beadcolors/raw, copy core/ into web/py
cli.py                 image -> pattern from the terminal
```

## Data: beadcolors

`../beadcolors/raw/*.csv` is the source of truth. Row format: `ref, name, r, g, b, contributor`
(no header). The repo is MIT licensed (keep its LICENSE alongside the vendored data).

- `build.py` copies `raw/*.csv` into `data/palettes/`. We use `raw/` only; Lab and symbols are
  computed by us, so we don't depend on its generated `gen/` folders.
- Pages can't read a sibling repo at runtime, so a vendored snapshot is committed.
  Updating = rerun `build.py`.
- MARD ships as two charts: `mard_291` (all of beadcolors' mard.csv) and `mard_221` (series A-H
  and M only; the code list matches the 221-color "basic" palette in
  Jett-Wu/Perler_Beads_Generator, but RGB values stay beadcolors'). `build.py` generates both.
- DMC (cross-stitch floss): `data/dmc_threadcolors.xlsx` holds the 454 DMC floss numbers with
  name and RGB, scraped from threadcolors.com by `tools/scrape_threadcolors.py` (one request;
  the table is in the front page). `build.py` turns the workbook into `data/palettes/dmc.csv`.
  DMC defaults to symbols on the chart (a bare number in a cell reads like a row number).
- Brands: dmc, mard_291, mard_221, perler (+mini, caps), hama (+mini, maxi), nabbi, artkal a/c/m/r/s, yant.
  `diamondDotz` is diamond painting, not beads, so it is hidden from the picker.
- Per-brand display names live in a small `BRANDS` table in `palette.py`
  (file stem -> label, bead size, shown-in-UI).
- Check at load: duplicate refs within a brand, and `artkal_m` row count (219 vs 174 in the
  upstream README) before trusting it.

## Pipeline

```
image bytes
  -> grid_detect   -> (period_x, period_y, offset_x, offset_y)     [user can override]
  -> clean         -> small RGBA array, one color per true pixel
  -> palette.match -> Pattern (indices into the chosen brand palette)
  -> render        -> PNG;  UI shows it + legend; print stylesheet -> browser print-to-PDF
```

### grid_detect
- Input may be a scaled (possibly non-integer) and/or blurred/JPEG'd pixel art.
- Cost is independent of image size: profiles use at most 256 evenly spread rows/columns, and
  x and y may differ in length (non-square images). A 3200x2000 image is detected in ~0.05 s.
- Per axis, build an edge profile (thresholded first + second differences, so JPEG noise is
  dropped and bilinear ramps still show their kinks). Pixel borders form a periodic pulse train.
- Spectrum of the profile: the real pixel size is the lowest-frequency line whose harmonics
  (2f, 3f, ...) are also strong. This rejects f/2 (weak odd harmonics) and multiples of f.
- Fine period by direct DFT around the peak; phase from the DFT angle. If the image is
  n cells wide to within 0.6%, the period snaps to width/n. Hard first-difference edges decide
  whether the phase marks borders (sharp pixels) or centers (bilinear ramps).
- No line stands out (prominence < 8): treated as 1:1. The UI always lets the user enter
  columns/rows manually.
- Known limits: patterns scaled by 2x or less, and heavy blur on sparse art, can miss.
  Tests cover sharp, JPEG-noisy and fractional upscales.

### trim / background (clean.py)
- `trim_border`: crops plain light rows/columns on all four sides, repeated until stable, so a
  gray screenshot frame, drop shadow and white canvas all go. Plain = one near-uniform light
  color (tolerates JPEG noise and faint editor gridlines). Dark rings are never trimmed.
- After sampling cells: `clear_background` empties near-white/transparent cells connected to
  the edge (4-neighbour flood fill; white inside an outline stays), `crop_to_content` drops
  empty outer rows/columns. Switchable ("Trim borders..." checkbox, `--keep-edges`).
- Grid detection allows non-square pixels (separate x/y periods when they differ by >4% and
  are not a 2-4x harmonic of each other).

### clean
- Per cell: median of the central region, ignoring blurred borders.
- Optional: merge colors within a small Lab distance, or cap the color count (k-means).
- Alpha below a threshold = empty cell (no bead).

### palette
- Match in CIELAB, ΔE2000 (CIE76 as fast path). Vectorised with numpy over unique colors only.
- Optional "colors I own" subset: filter the palette before matching.

### render / output
- Charts are SVG, not PNG: text and lines stay sharp on high-DPI screens and in a printed
  PDF (a raster is resampled by the browser, which is what made PNG charts look soft).
  "Download PNG" rasterizes the sheet SVG in the browser at up to 3x.
- Chart: colored cells with the bead code printed in each (works in grayscale and for
  color-blind users, so no separate symbol set), gridlines every 5, numbered rows/columns,
  split into evenly sized tiles of at most 32x40 cells. Legend is an HTML table (swatch, code,
  count) in the brand's own order (MARD: series letter, then number: A1, A2, ... A10, ... B1;
  natural sort, not string sort).
- Download PNG is the full chart; PDF via browser print (print CSS hides controls, one tile
  per page).

## Color swap, symbols, brand-first flow
- `Pattern.conversions()` lists each distinct source color, the bead it matched, and the 12
  nearest palette colors (dE2000). The page keeps `{rrggbb: ref}` swaps and sends them with
  every run; `build_pattern(swaps=...)` applies them per source color, so two similar shades
  that matched one bead can be sent to different beads. Swaps reset on a new image or brand.
- Cell labels: bead code, or a symbol (punctuation and geometric shapes, no letters or digits).
  Symbols are assigned in code order, so a color keeps its symbol whatever the list order.
  Brands whose codes are longer than 5 characters (Perler) default to symbols.
- The brand is chosen first; the image input unlocks once Python has loaded, and the pixel
  grid box only appears after an image has been processed.

## Speed and robustness (summary)
- Detection is 1D: edge profiles from <=256 sampled lines per axis, then an FFT. Cost does not
  grow with image area. Border trimming samples <=512 pixels per line.
- Everything after sampling works on the cell array (tens to thousands of cells), never on
  pixels; matching only compares unique colors. The decoded image and grid are cached, so
  the brand, colors, board size and order controls re-run only the cheap part.
- No pixel structure (edge density < 0.1% or no spectral line): <=150 px images are used
  1:1; bigger ones are treated as a photo and averaged down to 50 cells on the long side.

## Chart viewer
`web/viewer.js` shows each chart part (an SVG) in a box that fits it to the window by default;
zoom with the buttons, Ctrl/Cmd + scroll or pinch, drag to pan, double-click to toggle. Several
parts (pegboards, 52 cells per side by default) are shown one at a time with Prev / Next, or
all at once. Printing shows every part, one per page. While Python loads or an image is
processed, the status floats at the top of the screen so it is visible on a phone.

## Frontend

One page, system fonts, no framework, no bundler. Mobile-first: a single column by default
(controls, then preview), switching to two columns (controls left, preview right) on wide screens
via one media query. Touch-sized inputs (>= 44px), 16px+ base font to avoid iOS input zoom, file
input with `accept="image/*"`, preview canvas scales to container width with pinch-zoom/scroll
for large patterns. Controls: upload, brand, grid override, clean options. Preview: original /
detected grid / pattern.
`app.js` posts the image to `worker.js`, which loads Pyodide and calls `core`.

## Deploy

GitHub Pages serves `web/` (Actions workflow runs `build.py` and publishes). No backend, no storage.
